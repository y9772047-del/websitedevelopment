# 统计图表、热力图与轮盘图 
## 功能二：统计页图表化

当前统计页主要是数字卡片和任务完成率进度条。本轮将其升级为更适合展示的学习分析页面。

计划增加：

- 任务状态分布：展示未完成、进行中、已完成、延期任务数量。
- 优先级分布：展示 Q0、Q1、Q2、Q3 任务结构。
- 学习时长概览：继续展示总学习时长，并为后续趋势图预留结构。
- 完成率说明：不仅显示百分比，还显示完成任务数和任务总数。

实现方式：

- 优先使用原生 HTML/CSS/JavaScript 实现轻量图表。
- 不依赖新的 npm 包。
- 如果现有接口数据不足，先基于已加载的任务和记录数据在前端计算。

验收标准：

- 统计页有明显的图表或可视化元素。
- 图表颜色与现有主题系统兼容。
- 数据为空时有空状态，不出现 `NaN`、`undefined` 或布局塌陷。
- 移动端和桌面端都能正常浏览。

## 首页学习活跃热力图

竞赛网站中的热力图非常适合迁移到本系统首页，用来展示学生的持续学习行为。相比普通任务列表，热力图能更直观地表达“最近是否保持学习节奏”，适合作为优秀版首页的重要亮点。

放置位置：

- 优先放在首页工作台中，建议位于指标卡片下方、今日任务/最近学习记录上方或右侧统计区域。
- 作为首页第一屏或第二屏可见模块，标题建议为“学习活跃热力图”或“学习连续性”。

数据来源：

- 复用现有学习记录数据 `appState.records`。
- 使用 `studyDate` 作为日期。
- 使用 `duration` 作为热力值。
- 当天没有学习记录时显示浅色格子。
- 当天学习时长越长，格子颜色越深。

展示范围：

- 第一阶段展示最近 12 周或最近 90 天。
- 每个格子代表一天。
- 鼠标悬停可通过 `title` 显示日期和学习时长。
- 不依赖后端新增接口，不新增数据库字段。

视觉方向：

- 参考竞赛网站的绿色热力图，但与本系统主题色兼容。
- 低活跃为浅色，高活跃为绿色或主题色深阶。
- 模块保持白底、轻边框、圆角和克制留白。

验收标准：

- 首页出现学习活跃热力图模块。
- 热力图根据学习记录日期和时长渲染不同深浅。
- 没有学习记录时仍显示完整浅色网格和空状态说明。
- 不影响现有首页指标、最近任务、最近学习记录和 AI 建议。
- 前端语法检查和后端测试通过。

分类学习热力图筛选规则：

- 热力图筛选按钮固定为 `[ 全部 ] [ 课业完成型 ] [ 成绩提升型 ] [ 成长拓展型 ] [ 综合提升型 ]`，不再使用其他按钮名称。
- 全部：展示所有学习记录，包含“其他任务”。
- 课业完成型：包含“课程进度”“作业实验”。
- 成绩提升型：包含“考试备考”“复盘总结”。
- 成长拓展型：包含“竞赛科研”“专业能力”。
- 综合提升型：包含“自我提升”。
- “其他任务”不单独显示按钮，只计入“全部”。
- 前端实现时用集中映射常量维护按钮与分类关系，不把筛选判断散落在渲染逻辑里。

分类学习热力图颜色等级：

- 无记录：当天没有学习记录。
- 1-60 分钟：少量学习，用最浅的有效学习色。
- 60-120 分钟：常规学习。
- 120-240 分钟：有效投入。
- 240-360 分钟：高强度学习。
- 360 分钟以上：深度学习，用最深色。
- 等级只根据当天筛选范围内的总学习时长判断，颜色越深表示当天学习总时长越长，不再用记录条数推高颜色等级。
- 热力图色阶需要跟随主题皮肤变化，每个主题都应定义自己的 `--heatmap-level-0` 到 `--heatmap-level-5`，避免所有主题都显示同一套绿色。
- 浅粉主题偏玫瑰色，蓝色主题偏蓝色，绿色主题偏绿色，奶油主题偏暖金色，深色主题使用适合暗背景的紫蓝色阶。

## 首页学习计划投入分布轮盘图

首页新增“学习计划投入分布”轮盘图，用学习记录的学习时长解释不同学习计划的投入占比。该模块用于回答“我的时间主要投到了哪些学习计划上”，与分类学习热力图形成互补：热力图看连续性，轮盘图看投入结构。

时间范围：
- 最近30天：根据 `appState.records`、`appState.tasks`、`appState.plans` 临时统计。
- 最近180天：根据 `appState.records`、`appState.tasks`、`appState.plans` 临时统计。
- 全部：不再前端扫描全量记录，使用学习计划缓存字段统计。

数据库字段：
- 在 `study_plan` 增加 `total_study_minutes`，记录该计划历史累计学习分钟数。
- 在 `study_plan` 增加 `total_study_record_count`，记录该计划历史累计学习记录数。
- 数据库升级脚本需要根据已有 `study_record -> study_task -> study_plan` 关系回填两个字段。

维护规则：
- 后端启动时自动检查 `study_plan` 是否存在 `total_study_minutes` 和 `total_study_record_count`，不存在则补齐字段。
- 后端启动时根据已有 `study_record -> study_task -> study_plan` 数据回填一次计划历史投入，避免旧数据在“全部”范围下显示为空。
- 学习记录新增时，根据记录关联任务找到所属计划，给计划累计分钟数和记录数增加对应值。
- 学习记录编辑时，先扣减旧记录对应计划的分钟数和记录数，再增加新记录对应计划的分钟数和记录数。
- 学习记录删除时，扣减被删除记录对应计划的分钟数和记录数。
- 如果记录关联任务没有所属计划，不计入计划投入分布。
- 缓存字段只服务“全部”范围，最近30天和最近180天仍保持临时统计，避免把短期统计写入数据库。

展示规则：
- 标题固定为“学习计划投入分布”。
- 说明文字固定为“按学习记录统计不同学习计划在当前时间范围内的累计学习时长占比。”
- 时间范围按钮固定为“最近30天”“最近180天”“全部”，默认“最近30天”。
- 圆环图只显示单层扇区，不再叠加额外外环或浅色背景环，避免被误读为第二组数据。
- 每个扇区表示一个学习计划，扇区大小表示累计学习时长占比。
- 圆环中心主数字显示当前时间范围内的总学习时长，统一使用“X.X 小时”格式；副标题固定为“总学习时长”。
- 顶部摘要只显示当前时间范围、计划数和学习记录数，不再重复展示总学习时长。
- 图例显示计划名称、累计学习时长和占比。
- 如果计划数量过多，只展示学习时长最高的前 5 个计划，其余合并为“其他计划”。
- 鼠标悬停显示计划名称、当前时间范围、累计学习时长、关联学习记录数量和占比。
- 当前时间范围没有学习记录时，显示“暂无学习投入数据，新增学习记录后将自动生成计划投入分布。”

实现限制：
- 不修改顶部导航栏。
- 保留当前浅粉色主题，并使用现有主题变量。
- 不引入新的图表库，优先使用原生 HTML/CSS/JavaScript 和 `conic-gradient`。
- 首页刷新或切换时间范围时重新计算展示结果，但不能重复累计数据。
- 展示适配以桌面端和平板端为主，不考虑手机端适配。
