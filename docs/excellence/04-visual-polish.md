# 视觉升级、设计原则与验证 
## 设计原则

- 文档先行：每次功能改造前先更新 Markdown 文档。
- 小步改造：优先增强现有页面，不做大规模重构。
- 保持课程项目可讲解性：代码仍以 HTML、CSS、JavaScript 为主。
- 演示优先：优先提升答辩中最容易被看到的页面。
- 稳定优先：每轮改造后运行前端语法检查和后端测试。

## 首页工作台视觉升级

参考新的首页效果图后，首页继续保留顶部导航和浅粉色主题，但需要提升第一屏的产品感和数据层级。改造范围只限学生端首页，不改后端接口，不改学习计划、学习任务、学习记录等 CRUD 流程。

设计方向：
- 顶部增加欢迎横幅，展示用户问候、学习鼓励语和轻量学习场景装饰，让首页打开后更像真实学习工作台。
- 指标卡片保持四项核心数据：学习计划数量、任务总数、已完成任务、延期任务，但增加图标色块、昨日对比提示和更稳定的视觉层次。
- 今日学习焦点、风险提醒、计划执行进度、最近改进建议四个卡片升级为工作台行动区，强化“今天做什么、哪里有风险、整体进度如何、下一步怎么改进”。
- 分类学习热力图和学习计划投入分布继续作为首页核心可视化模块，位置保留在最近任务和最近学习记录之前。
- 热力图和圆环图是本轮视觉升级重点：热力图需要更清晰的周行标签、颜色图例和精简说明；圆环图需要更直观的单层占比结构、中心总学习时长、图例进度条、时间范围切换和空状态。
- 热力图和轮盘图是本轮视觉升级重点，分别表达学习连续性和学习计划投入分布。
- 首页分类学习热力图不再显示底部日期刻度，避免横向信息过密；热力图区不再重复展示活跃天数、累计投入、日均分钟和学习记录等统计卡片信息。
- 圆环图使用固定色板，不直接使用主题色作为扇区颜色；扇区颜色需要与右侧图例项、进度条和色标保持一致，避免不同计划看起来像同一类数据。
- 最近任务和最近学习记录保留双栏卡片，视觉上与上方模块统一。

实现原则：
- 只使用现有 HTML/CSS/JavaScript，不引入新的 UI 库或图表库。
- 使用现有主题变量，保持浅粉色主题，不改成蓝色或深色工作台。
- 不开发手机端适配，布局以桌面和平板宽度为主。
- 新增首页结构需要有静态测试守护，避免后续误删欢迎横幅、指标卡和工作台行动区。
- 可视化模块需要有静态测试守护，避免热力图和圆环图退化成普通列表或简陋色块。
