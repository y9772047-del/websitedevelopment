# 大学生学习计划管理系统项目综合报告

> 文档版本：1.0  
> 依据：当前项目代码、配置、数据库脚本与已有项目文档整理  
> 更新日期：2026-09-23

## 1. 项目背景与建设目标

大学生在课程学习、作业实验、考试备考、竞赛科研和个人能力提升等场景中，通常需要同时管理多个目标、截止日期与学习过程。仅依靠备忘录或分散文档，容易出现计划与任务脱节、学习投入不可量化、阶段问题无法沉淀、重要时间点遗漏等问题。

本项目是一个面向课程实践的学习计划管理系统 MVP。系统以“计划—任务—学习记录—反馈改进”为主线，帮助学生将学习目标拆分为可执行任务，记录实际投入与遇到的问题，并在仪表盘、统计和日历中集中查看进度。管理员可查看用户、任务和意见反馈的总体情况，以支撑课堂演示与基础运维。

项目的主要目标如下：

- 建立覆盖学习计划、任务、记录和重要节点的闭环管理能力；
- 以 Session 为基础实现普通用户与管理员的访问隔离；
- 通过学习记录和计划累计投入，提供进度、完成情况、热力图和计划投入等可视化信息；
- 将 AI 改进建议嵌入学习记录填写流程，减少独立“反思模块”造成的重复录入；
- 采用清晰的前后端分层和关系型数据模型，满足课程项目的可运行、可演示和可扩展要求。

## 2. 技术选型与运行环境

| 层次 | 技术/组件 | 说明 |
| --- | --- | --- |
| 后端框架 | Spring Boot 3.3.5、Java 17 | 提供 Web、拦截器、配置管理和 REST 接口。 |
| 数据访问 | MyBatis-Plus 3.5.7 | 实现实体映射和基础 CRUD，数据库字段使用 `snake_case`、Java 字段使用 `camelCase`。 |
| 数据库 | MySQL 8.x | 默认库名为 `study_plan_system`，字符集为 `utf8mb4`。 |
| 静态前端 | HTML、CSS、原生 JavaScript、Bootstrap 5 CDN | 主要用户端与管理员端页面均由 Spring Boot 静态资源服务。 |
| 独立前端实验 | Vue、Vite、Axios | `frontend/` 下保留独立 Vue 实验入口，与静态前端并存。 |
| AI 能力 | DeepSeek 兼容接口 | 用于生成学习改进建议和周报；未配置有效 Key 时应按后端兜底逻辑处理。 |
| 测试与质量 | Maven、Spring Boot Test、Node 语法检查、GitHub Actions | 用于后端构建、测试及静态 JS 语法检查。 |

默认服务监听 `http://localhost:8080`。数据库密码和 AI Key 分别从 `DB_PASSWORD`、`DEEPSEEK_API_KEY` 环境变量读取，不应写入源码或报告。

## 3. 项目总体结构

系统采用“浏览器页面 → REST API → Service/Mapper → MySQL”的分层结构。静态前端通过同源请求访问 `/api/**`；独立 Vue 前端通过 Axios 携带 Session 凭证访问同一后端。

```text
浏览器
├─ 静态用户端：index.html / pages/app.html
├─ 静态管理员端：pages/admin.html
└─ Vue 实验端：frontend/
        │ HTTP + Session Cookie
        ▼
Spring Boot
├─ WebConfig：CORS、登录与管理员拦截器
├─ Controller：认证、计划、任务、记录、统计等 REST API
├─ Service：业务校验、累计投入、AI 调用等业务逻辑
└─ Mapper：MyBatis-Plus 数据访问
        │
        ▼
MySQL：用户、计划、任务、记录、重要节点、反馈等数据
```

### 3.1 主要目录说明

| 路径 | 职责 |
| --- | --- |
| `src/main/java/com/example/studyplan/controller` | REST 控制器，负责请求参数、会话身份和接口响应。 |
| `src/main/java/com/example/studyplan/service`、`service/impl` | 业务接口及实现，例如记录保存时同步计划累计学习投入。 |
| `src/main/java/com/example/studyplan/mapper` | 基于 MyBatis-Plus 的数据访问接口。 |
| `src/main/java/com/example/studyplan/entity` | 实体及 AI 请求/响应对象。 |
| `src/main/java/com/example/studyplan/config` | 登录、管理员拦截器、CORS 和启动维护逻辑。 |
| `src/main/resources/static` | 登录页、用户端、管理员端以及原生 JS/CSS。 |
| `src/main/resources/db` | 建表脚本与增量升级脚本。 |
| `frontend` | 独立 Vue 前端实验实现。 |
| `src/test/java` | 后端与静态资源相关测试。 |
| `docs` | 实验说明、接口说明、验证记录和本报告。 |

### 3.2 静态用户端 JavaScript 结构

用户端入口为 `pages/app.html`，脚本按 `common.js → app.js → tasks.js → records.js → important-nodes.js → calendar.js → dashboard.js` 顺序加载。

- `common.js`：主题初始化和通用主题工具。
- `app.js`：全局状态、API 请求封装、计划管理、反馈、导航和启动调度。
- `tasks.js`：任务分类、增删改查、筛选、重复/提醒与批量导入。
- `records.js`：学习记录增删改查、AI 改进建议及展示。
- `important-nodes.js`：重要节点、关键词规则、批量导入和弹窗。
- `calendar.js`：月历渲染、月份切换、日期详情。
- `dashboard.js`：首页指标、任务提醒、热力图、计划投入轮盘和统计图。

该加载顺序存在跨文件全局依赖，调整脚本文件或全局函数时，应同步维护 `docs/frontend-js-dependencies.md`。

## 4. 核心数据模型与关系

### 4.1 主要表

| 表 | 核心内容 | 主要关系 |
| --- | --- | --- |
| `user` | 用户名、密码、姓名、角色、状态、创建时间 | 一个用户拥有多个计划、任务、记录、节点和反馈。 |
| `study_plan` | 计划名称、目标、周期、状态、累计学习分钟数、累计记录数 | 归属用户；可关联多个任务和重要节点。 |
| `study_task` | 任务名称、分类、优先级、截止日期、状态、重复与提醒设置 | 归属用户，必须关联一个学习计划；可关联多条记录和节点。 |
| `study_record` | 学习日期、时长、内容、完成情况、问题、改进计划 | 归属用户，必须关联一个任务。 |
| `important_node` | 标题、类型、日期/时间、重要程度、描述 | 归属用户，可选关联计划和任务。 |
| `important_node_keyword_rule` | 关键词、适用类型、影响方式、分值、启用状态 | 每个用户独立维护，用于辅助计算节点重要程度。 |
| `study_task_category` | 固定任务分类、排序、说明 | 被任务的分类字段引用。 |
| `feedback` | 用户反馈内容、处理状态、管理员回复 | 归属提交用户，由管理员处理。 |

### 4.2 关键业务约束

- 所有业务查询均以当前 Session 用户 ID 限定范围，避免普通用户访问其他用户的业务数据。
- 任务新增和修改时必须校验计划归属；学习记录新增和修改时必须校验任务归属。
- 任务分类为受控固定选项，优先级限定为 `Q0`、`Q1`、`Q2`、`Q3`。
- 学习记录的新增、修改、删除会同步更新关联计划的累计学习分钟数和记录数。
- 重要节点的类型、日期区间、关联计划/任务归属均会在后端校验；重要程度会结合类型、距离当前日期和用户关键词规则计算。

## 5. 项目模块说明与使用说明

### 5.1 认证与会话模块

**职责**：完成注册、登录、退出与当前用户查询；使用 HTTP Session 保存登录用户信息。

**主要接口**：`POST /api/auth/register`、`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/current`。

**使用步骤**：

1. 访问根路径进入登录/注册页。
2. 新用户填写注册信息；已有用户输入账号和密码登录。
3. 登录成功后进入 `pages/app.html`；管理员可访问 `pages/admin.html`。
4. 使用结束后通过退出操作清理当前 Session。

### 5.2 学习计划模块

**职责**：管理学习目标、计划周期、计划状态和累计学习投入，是任务组织的顶层对象。

**主要接口**：`POST /api/plans`、`GET /api/plans`、`GET /api/plans/{id}`、`PUT /api/plans/{id}`、`DELETE /api/plans/{id}`。

**使用步骤**：

1. 在“学习计划”页新建计划，填写名称、目标、开始/结束日期和状态。
2. 在计划详情查看关联任务及执行进度。
3. 编辑计划时保持日期范围和状态与实际学习安排一致。
4. 删除前确认关联任务和记录的影响，避免误删课堂演示数据。

### 5.3 学习任务模块

**职责**：将计划拆解为可操作的学习事项，并提供分类、优先级、截止日期、状态、重复规则、提醒和批量导入能力。

**主要接口**：`POST /api/tasks`、`POST /api/tasks/batch`、`GET /api/tasks`、`GET /api/tasks/categories`、`GET /api/tasks/{id}`、`PUT /api/tasks/{id}`、`PATCH /api/tasks/{id}/status`、`DELETE /api/tasks/{id}`。

**使用步骤**：

1. 先创建学习计划，再在“学习任务”页选择所属计划。
2. 选择受控分类和 `Q0` 至 `Q3` 优先级，填写截止日期与任务状态。
3. 对固定频率事项配置每日、每周或工作日重复规则及结束日期。
4. 使用筛选条件查看不同计划、状态、优先级或日期的任务；批量导入前按页面给出的格式检查每一行。

### 5.4 学习记录与 AI 改进模块

**职责**：记录实际学习过程、用时、完成情况和问题；根据记录内容生成可确认、可编辑的改进计划。

**主要接口**：`POST /api/records`、`GET /api/records`、`GET /api/records/task/{taskId}`、`GET /api/records/recent`、`PUT /api/records/{id}`、`DELETE /api/records/{id}`；AI 接口为 `POST /api/ai/generate-improvement` 和 `POST /api/ai/generate-weekly-report`。

**使用步骤**：

1. 选择已有任务，填写学习日期、学习时长、学习内容和完成情况。
2. 如遇到困难，在“问题/反思”中记录事实与原因。
3. 点击 AI 建议按钮，核对生成内容；可修改后再保存到学习记录的改进计划字段。
4. 在记录列表或按任务时间线复盘历史过程。记录变化会同步影响计划累计投入和部分统计视图。

### 5.5 首页驾驶舱与统计模块

**职责**：聚合计划、任务和记录，展示计划数、任务数、完成任务数、延期任务数、最近任务、最近记录、任务提醒、分类热力图和计划投入轮盘。

**主要接口**：`GET /api/dashboard`、`GET /api/statistics`。

**使用步骤**：

1. 进入“首页”查看当前汇总与近期事项。
2. 通过热力图查看不同日期和任务分类的学习投入。
3. 使用计划投入轮盘比较多个计划的累计学习时长和记录数量。
4. 当统计数据异常时，优先检查任务是否关联计划、记录是否关联任务，以及学习日期和时长是否完整。

说明：统计页面对应的 HTML 与脚本逻辑仍保留，但当前用户端顶部导航未展示独立“统计”入口。

### 5.6 学习日历与重要节点模块

**职责**：按月份呈现学习记录、任务截止日期和重要事件；重要节点支持考试、截止、比赛、汇报、其他类型，以及批量导入与关键词规则。

**主要接口**：`GET /api/calendar?year={year}&month={month}`；重要节点接口为 `/api/important-nodes`；关键词规则接口为 `/api/important-node-keyword-rules`。

**使用步骤**：

1. 在“学习日历”切换月份并点击日期，查看当天学习记录、截止任务与节点详情。
2. 在“重要节点”页新增或编辑事件，填写类型、起止日期和可选的计划/任务关联。
3. 对多条事件使用批量导入前先遵循页面格式；导入后检查日期范围和重要程度。
4. 在关键词规则中设置个人关键词及影响方式，用于辅助识别重要或紧急节点。

### 5.7 意见反馈模块

**职责**：允许学生提交系统使用反馈，并查看自己的反馈处理状态；管理员可回复和更新状态。

**主要接口**：`POST /api/feedback`、`GET /api/feedback/my`；管理员端使用 `/api/admin/feedbacks` 及其详情、更新接口。

**使用步骤**：学生在“意见反馈”页提交问题或建议，随后查看“我的反馈”；管理员在后台筛选、查看并回复反馈，更新为已处理或已忽略。

### 5.8 管理后台模块

**职责**：向管理员提供全局统计、用户管理、学习任务管理和反馈处理能力。

**主要接口**：`/api/admin/dashboard/stats`、`/api/admin/users`、`/api/admin/tasks`、`/api/admin/feedbacks` 及其详情、状态/回复更新接口。

**使用步骤**：

1. 使用管理员角色账号登录后访问 `pages/admin.html`。
2. 在后台首页查看总体统计。
3. 在用户管理页查看用户详情和启停状态；在任务管理页查看或删除异常任务。
4. 在反馈管理页处理用户意见。

管理员接口和页面受管理员拦截器保护，普通用户访问会被拒绝。

### 5.9 主题皮肤模块

**职责**：提供 5 套内置主题，并通过浏览器 `localStorage` 保存用户的主题选择。

**使用步骤**：进入“主题皮肤”选择预设主题；刷新页面后系统会读取本地保存的选择。该偏好存储在浏览器本地，不写入后端数据库。

## 6. 访问控制、配置与安全边界

### 6.1 访问控制

- `LoginInterceptor` 拦截 `/api/**`，但排除 `/api/auth/**`；未登录请求返回 401。
- `AdminInterceptor` 拦截 `/api/admin/**` 和 `/pages/admin.html`；非管理员请求返回 403。
- CORS 仅接受配置中的显式来源，且启用凭证；配置中禁止使用通配符来源。
- 普通业务控制器在查询、详情、更新、删除时使用当前用户 ID 限定数据归属。

### 6.2 当前课程项目中的限制与改进建议

项目 README 已明确说明，当前实现为课程演示简化了密码处理，数据库中存在明文密码设计。正式部署前至少应完成以下改造：

1. 使用 BCrypt 等强哈希存储密码，并规划历史密码迁移；
2. 为登录增加限流、失败审计与更严格的会话策略；
3. 对用户输入做服务端长度、格式和内容校验，并在前端渲染时持续进行 HTML 转义；
4. 将 AI Key、数据库密码等敏感配置交由环境变量或密钥管理系统托管；
5. 为删除、批量导入和管理员状态变更补充审计日志、确认机制和回滚策略；
6. 在生产环境收紧 CORS 来源、部署 HTTPS，并完善备份恢复和监控告警方案。

## 7. 部署、初始化与验证建议

### 7.1 本地运行步骤

1. 安装并启动 MySQL，创建或确认可用数据库服务。
2. 执行 `src/main/resources/db/schema.sql` 初始化数据库和固定任务分类。
3. 设置 `DB_PASSWORD`；如需启用外部 AI，再设置 `DEEPSEEK_API_KEY`。
4. 使用 Java 17 环境运行 `StudyPlanSystemApplication`，或执行 Maven 构建后启动。
5. 访问 `http://localhost:8080`，注册普通用户并按“计划 → 任务 → 学习记录 → 日历/仪表盘”顺序进行验收。

### 7.2 推荐验收场景

| 场景 | 预期结果 |
| --- | --- |
| 注册、登录、退出 | Session 状态正确建立和清除；未登录 API 返回 401。 |
| 新建计划、任务、记录 | 任务只能关联本人的计划，记录只能关联本人的任务。 |
| 修改/删除学习记录 | 关联计划的累计时长、记录数量和仪表盘数据同步变化。 |
| 任务筛选、重复、提醒、批量导入 | 受控分类和优先级校验有效；重复日期与提醒参数符合规则。 |
| 月历与重要节点 | 指定月份展示记录、任务截止日期和节点；跨日期节点的范围正确。 |
| 普通用户访问后台 | 被管理员拦截器拒绝，返回 403。 |
| AI 建议 | 有效 Key 时获得外部建议；无有效 Key 时按系统兜底策略处理，不影响记录保存。 |

## 8. 总结

该系统围绕学习过程管理建立了清晰的实体关系和功能闭环：学习计划定义方向，学习任务承接执行，学习记录沉淀投入与问题，仪表盘、统计和日历提供反馈，重要节点保障时间安排，管理员后台提供基础治理。当前实现适合课程项目演示与学习管理场景验证。

后续迭代应优先处理密码安全、审计与异常处理等工程化能力，并在不改变用户数据归属边界的前提下，逐步增强通知提醒、数据导出、权限细分和自动化测试覆盖。
