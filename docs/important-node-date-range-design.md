# 重大事件跨日期支持设计

## 目标

将“重大事件 / 学习日历事件”从单个日期扩展为日期区间，支持单日事件和跨日期事件。

## 数据结构

前后端统一使用以下字段：

```json
{
  "id": 1,
  "title": "数模校赛",
  "type": "比赛",
  "startDate": "2026-06-20",
  "endDate": "2026-06-22",
  "description": "校内选拔赛"
}
```

## 保存规则

`startDate` 和 `endDate` 都必填。单日事件保存为相同的 `startDate` 和 `endDate`。如果 `endDate` 早于 `startDate`，前端阻止提交并提示“结束日期不能早于开始日期”；后端也返回同样错误，保证批量导入或接口调用不会绕过校验。

## 列表和日历展示

年度列表查询需要包含与该年份有交集的事件：`startDate <= 年末` 且 `endDate >= 年初`。列表按 `startDate`、开始时间、创建时间排序，并显示日期区间；单日事件只显示一个日期。

学习日历按天展开跨日期事件。一个跨日期事件会出现在区间内的每一天，详情面板展示同一个事件，并保留时间、类型、重要程度和描述。

## 表单顺序

单个新增/编辑表单按时间线排列字段：

```text
开始日期 | 开始时间 | 结束日期 | 结束时间
```

开始时间和结束时间仍为选填。跨日期事件可以填写开始日期、结束日期，也可以补充具体起止时间。

## 批量导入

批量导入格式改为：

```text
标题 | 类型 | 开始日期 | 开始时间 | 结束日期 | 结束时间 | 重要程度 | 描述
```

为了兼容旧格式，如果只提供一个日期，则自动作为单日事件处理，即 `endDate = startDate`。

## 测试范围

后端增加校验测试：结束日期早于开始日期时拒绝保存并返回指定提示；单日事件可正常保存并补齐结束日期。静态资源测试覆盖页面字段和批量导入解析关键文本。
